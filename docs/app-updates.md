# 应用内更新

0.7.9起，氢贴吧启动后会在后台检查公开仓库 `moying32/HTieba` 的 GitHub Releases；设置首页和关于页都提供“检查更新”入口。包含正式版和预发布版，按语义版本选择适用APK，不能以发布时间或字符串大小判断版本。0.7.9+updatefix.1优先读取GitHub公开Releases Atom订阅及附件页面，公开页不可用时才尝试REST API（最近30条）；订阅范围以GitHub实际返回的条目为准。

## 使用方式

1. 首次手动安装0.7.9或后续包含此功能的版本。已安装的0.7.6不会自动获得更新功能。
2. 以后冷启动时后台检查。新版提示提供更新说明、版本、包大小，以及“下载更新”“稍后提醒”“跳过此版本”。没有新版、检查失败或已跳过的版本不会在启动时弹窗打断阅读。
3. 下载在应用内完成，可查看进度或取消。下载完成后点击“安装更新”；首次需要在系统设置允许氢贴吧安装应用，然后在系统安装器确认。覆盖安装保留原应用数据。
4. “跳过此版本”保存在本机，仅抑制这个版本的启动提示。手动检查仍能查看和安装该版本；更高版本发布后重新提醒。“稍后提醒”不持久化跳过。

检查或下载失败会显示原因并允许重试；没有可识别版本、GitHub公开页与备用接口均不可用、新版未附适用APK分别提示，不冒充“已经是最新版”。网络不可达时可继续原有阅读，当前没有第三方下载镜像。

## 发布维护

- 在 `app/build.gradle.kts` 更新 `versionName` 与严格递增的 `versionCode`；采用 `0.7.9`、`0.8.0` 或 `0.8.0-beta.1` 等SemVer格式。
- 完成构建及验证，将APK作为公开GitHub Release附件上传，tag与APK内的版本名称保持一致，例如tag `v0.7.9` 对应 `versionName=0.7.9`。
- 推荐唯一附件名 `HTieBa-0.7.9.apk`。当前构建为通用APK；如果改成多架构，须保留唯一同版本标准名称的通用包或唯一名称含 `universal` 的APK，不能让客户端猜架构。
- 必须沿用用户已安装版本的签名证书。当前包仍使用开发测试签名；更换到正式证书需要独立迁移方案。本版不支持证书轮换链升级。
- 公开页路径从附件行提取可用SHA256，通过同一附件URL的HEAD响应取得精确字节长度，不能将页面显示的四舍五入KB/MB作为校验大小；下载仍核对内容长度和摘要。REST备用路径使用GitHub返回的asset大小和可用SHA256摘要；不需要token、额外更新服务器或 `update.json`。未附摘要的旧asset仍必须通过APK签名、包名和版本检查。
- 草稿发布不会生效，预发布会参与检查；删除或遗漏APK时不会提供无效下载入口。源码上传、tag和Release附件是不同步骤，仅上传代码不能让用户收到更新。

## 安装与数据边界

更新请求使用独立HTTPS客户端，不携带贴吧Cookie、凭据或安装标识。只接受本仓库Release下载路径，重定向仅允许GitHub官方资源域名。APK保存到应用私有目录，最多200MB；下载及安装前核对字节长度、可用SHA256摘要、同包名、匹配Release的版本名称、递增版本号、同签名和最低系统版本。

系统安装器通过限于 `files/updates/` 的FileProvider临时读取APK，无需广泛存储权限。不支持静默安装；用户须在系统确认。下载被取消或失败时清理本次临时文件，重新下载使用独立文件，防止上一请求的迟到回调影响重试。进程被系统终止后可重新下载，不提供断点续传或后台保活服务。

本版实现与验证边界见[0.7.9记录](iteration-079.md)。

## 限流修复测试包

`apks/HTieBa-0.7.9-updatefix.1.apk`是本地测试修复版，versionName为`0.7.9+updatefix.1`，保留versionCode33，以便现有9.5.0/code34空壳仍能用于升级测试；未覆盖原0.7.9 APK。构建元数据不改变SemVer排序。此安排仅用于本次测试，后续发布功能版仍须递增versionCode。

公开页解析依赖jsoup 1.21.2，不执行页面脚本或解析外部XML实体。只访问GitHub官方域名，不内置token或引入第三方代理。GitHub网页结构变化可能触发REST备用路径；两条路径都失败时保留重试错误，不能承诺任意网络均可访问。
