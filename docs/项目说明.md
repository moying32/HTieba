## 1. 项目概述

氢贴吧是使用 **Kotlin / Jetpack Compose** 开发的 Android 第三方百度贴吧客户端。项目通过研究贴吧官方客户端协议接入真实业务，过滤已识别的广告数据，重新设计原生界面，目标是成为能够替代官方客户端日常使用的完整贴吧客户端。

产品的信息架构和操作效率参考 X：紧凑内容流、推荐与关注分流、稳定的发布入口、直接的回复操作、消息与个人空间。同时保留贴吧自己的社区结构，包括吧、带标题的帖子、楼层、楼中楼、吧务身份和吧内等级。

项目覆盖的完整目标是：**找内容 → 浏览与阅读 → 关注社区和用户 → 发帖与回复 → 接收通知及聊天 → 管理账号与社区**。阅读、收藏和主题只是阶段成果，不能据此认定完整客户端已经完成。

应用直接呈现百度返回的内容与排序，不建立本地推荐算法；不使用虚构帖子、身份、计数、会话或本地成功状态冒充真实业务结果。

## 2. 产品原则与能力边界

1. **真实业务优先。** 内容、账号、关系和互动结果必须来自服务端。接口缺失的信息应隐藏或明确说明，不补造数字与身份。
2. **原生体验优先。** 核心阅读、编辑、列表、通知和会话采用 Compose。官方 HTTPS 页面承担登录、安全验证及部分尚未原生完成的能力。
3. **阅读效率优先。** 减少首屏装饰，保持信息密度、中文可读性、滚动稳定和及时反馈。
4. **交互状态完整。** 操作需要有按压、加载、成功、失败和禁用状态，并支持系统返回、键盘与无障碍语义。
5. **明确记录完成程度。** 设计稿、代码接入、自动检查和真实账号验证分别记录。旧版验收不能直接作为新版全量验收。

“去广告”是产品方向和已识别广告字段的过滤策略，不代表所有接口、所有广告变体已经验证。推荐、关注和吧内帖子应保持各自真实来源，不能用其他列表替代空态。

## 3. 信息架构与主要使用流程

主导航采用五项悬浮胶囊：**刷帖、逛吧、发帖、消息、我的**，其中发帖以加号呈现。

| 入口 | 主要内容与路径 |
| --- | --- |
| 刷帖 | 推荐内容、关注内容、搜索入口；进入帖子后可阅读、互动、看图和播放已有视频 |
| 逛吧 | 搜索吧、关注吧、推荐吧、最近访问和签到；进入吧后查看资料与帖子 |
| 发帖 | 选吧、标题、正文、图片、草稿、预览与确认提交 |
| 消息 | 点赞、回复、@通知及原生会话入口；支持定位相关帖子和楼层 |
| 我的 | 真实账号资料、关系、收藏、历史、自己的内容、资料编辑、管理我的吧和设置 |

从帖子、搜索、个人页或另一个吧进入吧页面时，应记录来源并返回原页面。返回详情前的列表应尽量恢复阅读位置。聊天页使用独立页面层级，隐藏主导航，返回收件箱或原进入来源。

发帖入口必须由明确点击触发；导航透镜拖动经过加号不能自动发布或进入提交。

## 5. 内容、社区与互动细节

### 5.1 信息流与帖子结构

帖子采用整体玻璃卡片。作者区包含真实头像、昵称、可用的等级/称号/吧务身份、时间与更多操作；内容依次组织所属吧、标题、摘要和附件。所属吧可点击。

卡片操作包含点赞、百度云收藏、评论、本地收藏和分享五项。百度未返回云收藏数时隐藏数字，真实返回 0 时显示 0；本地收藏与云收藏独立保存，不自动合并。

头像、图片徽章、吧内等级与身份遵循接口字段及客户端/位置可见性。提及用户仅在存在真实身份信息时提供对应主页跳转。

分页按真实 ID 去重并保留顺序；没有新 ID 时应停止无效加载。吧后续页的占位元数据不能覆盖首页真实资料，也不能仅据此将真实存在的吧误判为不存在。

### 5.2 阅读与回复

详情保留楼层与楼中楼结构，采用紧凑评论、小配图、次级元信息和回复摘要。支持正文复制、真实时间/属地、评论分页、只看楼主和跳页。通知进入帖子时应保留原帖与楼层上下文。

回复框需要考虑键盘、安全区、草稿恢复、关闭后返回原对话和重复点击。只有服务端明确成功才更新发送结果，失败或结果不明时保留输入，不自动重复发送。

此前线程点赞、取消点赞和普通评论的真实验证仅在用户指定测试帖中进行；这些记录不意味着所有写接口、所有账号和任意帖子均已验证。

### 5.3 搜索、链接与表情

搜索支持帖子、吧、用户；热榜来自贴吧接口。搜索历史默认展示 4 条，可展开更早记录。支持输入帖子 ID、帖子链接和带 `kw` 的吧链接。

Manifest 已声明贴吧 HTTPS `/p/` 与 `/f` 链接入口，但 `autoVerify=false`，不同系统的外部链接分发仍需测试。

贴吧表情按经典及接口资源呈现，支持内联图片、GIF、复制和无障碍描述；未知或加载失败的资源回退到文字描述。

## 6. 图片与视频体验

### 6.1 图片预览与下载

- 同帖或同楼多图可手势翻页，也可使用上下张按钮；按钮与手势使用同一分页状态，连续和反向操作可中断续接。
- 支持双指缩放、双击缩放及放大后的平移；复位后恢复正常翻页，松手处理边界。
- 低、中、高、原画四档画质只在设置中选择，预览中不常驻画质、分辨率和缩放提示胶囊。
- 工具栏单击显隐使用约 260 / 240 ms，双击缩放约 180 ms，并支持减弱动效与系统动画设置。
- 保存百度返回的原文件字节，自动创建系统 **`Download/HTieBa/`** 目录和唯一文件名，无需反复选择位置；当前下载大小上限为 80 MB。

Android 10 及以上使用 MediaStore 的待发布/发布机制并清理失败项；Android 8/9 需要相应存储权限。已有真实 JPEG 下载与字节摘要核验记录。服务器返回资源的清晰度仍受原地址限制，不能把放大缩略图称作原图。

### 6.2 已发布视频播放

使用 Media3，采用用户选定的 B「悬浮 Orbit」布局。液态玻璃浮岛固定于屏幕底部上方，保留安全距离；上方显示两端时间和细进度，下方为较大播放按钮、倍速、静音与唯一全屏按钮。

播放器按实际播放时钟逐帧更新可见进度。左右各约 35% 区域长按可临时 2 倍速，松手、取消和进入后台时恢复原速；普通播放约 2.5 秒自动隐藏控制，菜单、拖动与相关交互期间保持可用。保留媒体原比例及全屏方向恢复。

0.6.6 已验证实际进度连续移动、拖动定位、暂停保持、倍速菜单和横竖屏恢复；这些记录不能替代当前 0.7.1 的完整回归。**播放已有视频与发布视频是两项能力，后者仍未完成。**

## 7. 发布、账号与本地数据

### 7.1 图文发布

原生分层编辑器包含账号、选吧、标题、正文、图片、预览和确认提交；支持按账号保存草稿、最多选择 9 张图片，并呈现提交状态。未知结果时提示核对，避免自动重发。

当前上传路径会将图片最长边限制到 2048 像素、使用约 88% JPEG 质量并限制编码文件不超过 8 MB，且仅在确认发布后上传。因此，图片下载保存原文件与发帖上传压缩图片应分别描述。

真实图片上传、新帖发布、媒体评论和完整富媒体发布仍需补齐或验收。历史主帖原生编辑尚未完成，保留官方入口。

### 7.2 登录与个人空间

账号密码及安全验证在百度官方 HTTPS 登录页面完成；原生层使用本应用 WebView 会话的 BDUSS 认证请求，不读取官方客户端私有数据，不额外导出明文令牌文件。

个人页展示真实账号、头像和关系数量；关注/粉丝胶囊位于头像右侧，可进入真实列表。个人主页背景使用接口返回的背景并向主题底面渐变，也可在本机替换或恢复；本机换背景不等于上传修改百度资料。

昵称、简介、性别编辑已有表单和保存协议，头像、星座修改及部分账号业务尚未完成。账号名称、头像和刷新已有验证，完整登录/失效/退出仍需专项验收。

### 7.3 本地存储与隔离

本地使用 SharedPreferences、JSON 与文件存储保存设置、收藏、历史、草稿、主题和缓存。主要数量边界如下：

| 数据 | 当前边界 |
| --- | --- |
| 浏览历史 | 最多 100 条 |
| 搜索历史 | 最多 20 条 |
| 最近访问吧 | 最多 12 个 |
| 本地收藏 | 最多 1,000 篇 |
| 自制主题 | 最多 20 款 |
| 聊天持久缓存 | 每账号最多 100 个会话，每会话最近 400 条消息 |

发帖、回复和聊天草稿按账号隔离；会话置顶、本地收藏及“本机未看”等聊天状态也按账号隔离。不能把所有阅读历史、全局偏好都描述为账号独立。聊天运行期间已加载的更早历史与持久缓存上限分别处理，草稿单独保存。

本地数据不自动成为云端收藏、云端未读或跨设备同步。当前没有可承诺的完整云备份/恢复能力；卸载应用会清除应用内本地数据，下载到公共目录的媒体与应用内部数据应分别管理。

## 8. 消息、私信与吧群

### 8.1 原生界面与本地操作

当前采用用户选定的 C「紧凑对话流」：顶部为点赞、回复和 @ 通知胶囊，主体为原生会话列表，支持私信、吧群和“本机未看”筛选。会话内采用头像、真实名字和正文层级，自己的消息使用柔和主题背景。

已实现会话/消息搜索、按账号草稿、置顶、左滑引用、长按回复/复制/本地收藏/多选、搜索上下个，以及群资料、公告和共享内容定位。引用摘要可定位已加载的原消息；发送引用采用明确的文字引用，不冒充百度原生回复关系。

搜索覆盖已加载及本机缓存内容。“本机未看”、置顶和收藏是本地状态，不能显示为百度云端未读、已读回执或完整云历史。

### 8.2 数据与传输

群目录、群资料、公告和分页历史复用百度 HTTPS 接口。0.7.1 中收件箱和会话在前台每 15 秒同步，切换会话取消旧读取，离开前台时停止；进行中的显式发送不自动重试。当前没有后台推送或完整实时消息能力。身份和附件仅在接口返回对应字段时呈现。

`GroupChatTransport.kt` 接入 LCM 凭据、TLS BLCP 登录、IM 身份和群文字发送，校验系统证书与主机名。它不自动加群、不自动重发，只在成功回执后加入本地消息，并与历史中的同一回执合并，保留真实的重复文本。失败或结果不明时保留草稿及引用。

`ChatWire.kt` 实现旧私信 WebSocket/protobuf、RSA 密钥交换、PBKDF2-HMAC-SHA1 派生、AES-ECB 消息处理、登录、同步窗口和文字发送。0.7.0 中该通道关闭；用户明确授权后，**0.7.1 已启用 `PrivateChatConnection.ENABLED=true` 并完成构建**，端点为 `ws://im.tieba.baidu.com:8000/`。

专用 OkHttp 客户端通过应用拦截器添加百度握手版本标记，修复直接设置扩展头不兼容及 WebSocket 跳过网络拦截器的问题。响应按命令与序号共同匹配；只有服务端确认消息 ID，且返回的收件人/本地标识不存在冲突时才显示发送成功。新消息组加入后续同步范围，账号切换、取消登录和旧回调按会话代次隔离。

私信仅展示接口返回窗口和本机缓存。缺少收件人字段的自身记录不能错误归入“自己”的会话；显式发送消息由成功回执保存。未知消息保留类型和接口文本，不拼造媒体地址。

### 8.3 私信传输边界与验证程度

`network_security_config.xml` 默认禁止明文，仅对 `im.tieba.baidu.com` 单域名放行，不包含子域名；专用客户端拒绝其他主机和跳转，其他业务继续使用原有 HTTPS 接口及证书校验。

**首次私信登录的 BDUSS 字段缺少 HTTPS/TLS 保护。** 它不在 RSA 密文内，协议 `1001` 登录包也未使用 AES 封装。因此不能用“RSA/AES 加密”概括整个登录与通信过程，也不能将这套旧协议描述为现代安全通道。应用在私信入口明确说明，并在错误提示及会话资料保留官方私信入口。

公开端点探测和实际 `PrivateChatProtocol.client()` 的无凭据探测均收到 `101 Switching Protocols`；本地回环模拟服务也覆盖握手、登录包、历史解析和回执。但这些验证没有使用真实百度账号，不能证明账号登录或真实收发可用。

历史版本已有群目录/资料/历史只读验证；当前新身份解析、原生布局和群发送仍待真实验证。完整私信收发验收、媒体附件、完整群成员列表、撤回、编辑、云端未读同步和后台推送仍有缺口。不展示虚构的在线、输入中或已读状态。旧连接授权不包含向真实账号发送测试消息的授权。

## 9. 视觉、动效与可访问性

### 9.1 设计依据

项目按 `AGENTS.md` 与 `docs/design-guidelines.md` 落实 Emil Kowalski 的设计原则，重点是清晰层级、及时反馈、手势连续性、有目的的动效与性能。网页示例只作交互参考，实际实现使用 Android 原生语义。

绿色配色、整帖玻璃卡片、圆角、五项悬浮导航和具体字体属于本项目选择，并非上游原则强制的固定视觉。

### 9.2 布局与触控

正文与评论保持紧凑；视觉胶囊按内容包裹，减少重复大背景。0.7.0 进一步收紧内容气泡，部分视觉背景最低约 30 dp、菜单背景向内收约 5 dp，同时保证真实可点击区域至少 **48 dp 物理尺寸**。

正文/评论/楼中楼默认字号为 **16 / 15 / 14 sp**，阅读大字号为 **19 / 18 / 17 sp**。字体倍率为 **50–150%，1% 步进**；界面倍率为 **50–150% 连续调节**，提供 50/75/100/125/150% 常用档。两者独立预览、重置、应用与保存，触控目标不能随视觉缩放而失去可用面积。

界面需覆盖浅色、深色、长中文、大字体、窄屏、加载、空态、错误重试、分页和键盘场景。图标提供语义，颜色不能独自承担状态表达；系统返回与页面返回保持一致。

### 9.3 玻璃与运动

- 液态玻璃主要用于导航、输入、菜单和悬浮操作，避免给重复小控件配置昂贵的独立采样或采样自身。
- Android 13 及以上提供局部 AGSL 背景位移与轻微色散；Android 12 使用模糊，更早系统采用半透明材质。允许关闭增强效果。
- 导航透镜拖动直接跟手，松手按速度弹簧归位，快速反向与重新触摸可中断。
- 顶栏按实际滚动距离连续移出和露出；底栏保留既有收放，关闭自动收起后顶栏常显，“我的”根页底栏常驻。
- 当前主导航过渡约 200 ms，包含小幅定向位移、淡化和不超过约 5 dp 的模糊；次级页面约 220 ms。以最新实现为准，旧文档的更早过渡参数不再视为当前规范。
- 高频列表不逐项播放装饰性入场，动效尊重减弱动效与系统设置。

现有玻璃与短时滚动只在有限设备和场景下验证，不能推断全部机型、低端设备和长期刷帖性能。当前聊天页面的 TalkBack、键盘、手势和倍率组合仍需设备验收。

## 10. 主题、字体与设置

内置 **经典、映间 MARGIN、Claude 风**三类视觉风格，各自保存主题色，支持浅色、深色及跟随系统。Claude 风仅是视觉选择，不接入 Claude 服务；映间为视觉参考，应用仍是原生 Compose 实现。

设置分为六类：**外观与主题、字体与界面、阅读与媒体、交互与动效、账号、关于氢贴吧**。“我的”仅保留一个设置入口。

## 12. 接口协议、数据正确性与会话安全

只读接口主要使用 `https://tieba.baidu.com`，认证 App 请求使用 `https://tiebac.baidu.com`；群功能还使用 `pim.baidu.com` 相关 HTTPS 接口及 TLS 传输。各接口可能使用不同兼容客户端版本，不能统一替换为应用自身版本号。

当前 App 请求签名的基本规则为：排除 `sign`，按键排序拼接 `key=value`，末尾追加协议字符串 `tiebaclient!!!`，计算大写 MD5。具体参数和兼容处理以 `NativeProtocol.kt` 与调用代码为准。

| 业务 | 代表接口路径 |
| --- | --- |
| 吧帖子 / 详情 / 楼中楼 | `/c/f/frs/page`、`/c/f/pb/page`、`/c/f/pb/floor` |
| 推荐 / 推荐吧 | `/c/f/excellent/personalized`、`/c/f/forum/forumrecommend` |
| 账号 | `/c/s/login`、`/c/u/user/profile` |
| 点赞 / 评论 / 发帖 | `/c/c/agree/opAgree`、`/c/c/post/add`、`/c/c/thread/add` |
| 粉丝 / 关注 | `/c/u/fans/page`、`/c/u/follow/followList` |
| 云收藏 | `/c/f/post/threadstore` 及 `addstore` / `rmstore` 对应调用 |
| 签到 | `/c/c/forum/sign` |

解析需要兼容根级用户列表与内容中的作者 ID 关联，保持真实身份和内容顺序；字段缺失不能生成虚假的作者、等级、统计或成功状态。写请求需检查服务端错误和有效业务 ID，防止登录失效或风控页被误判成功。

账号凭据只来自本应用官方页面会话。安装身份使用随机标识，不采集硬件标识用于伪造设备。Manifest 配置 `allowBackup=false`、`usesCleartextTraffic=false`，官方网页 Activity 不对外导出；存储权限仅用于旧系统相应场景。0.7.1 同时引用网络安全配置：默认禁止明文，但对 `im.tieba.baidu.com` 单域名放行，且不包含子域名；因此不能仅凭 Manifest 总开关断言没有明文连接。

密码输入的官方 HTTPS 页面与后续原生私信认证是两个环节。前者使用 HTTPS，不代表后者传输的 BDUSS 也有 TLS 保护；首次私信登录的具体边界见第 8.3 节。

贴吧业务 API 客户端关闭自动连接重试与重定向，写操作串行约束避免重复提交；发送结果不明时保留草稿、要求核对，不以本地乐观状态声称业务成功。媒体下载等独立客户端有各自策略，不能将上述配置泛化到所有连接。密码、Cookie 和令牌不应写入普通调试输出。

上述接口是持续研究和适配的非官方稳定契约，服务端变更可能导致失效，需要通过解析测试、错误状态和真实业务验证持续维护。
