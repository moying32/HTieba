## 账号与写操作

0.2.0 在用户完成官方 HTTPS 登录后，通过本应用 WebView 的 CookieManager 读取自身会话中的 BDUSS，并由 `/c/s/login` 确认账号和取得操作用的 tbs。原生“我的”页显示查询得到的头像和昵称，支持刷新、会话失效提示和退出。密码不会进入原生输入框；没有读取官方客户端的私有账号数据，没有额外保存或输出令牌。

| 路径 | 本版用途 | 验证状态 |
| --- | --- | --- |
| `/c/s/login` | 原生账号信息及 tbs | 空凭据实测返回错误码 2，已登录成功分支待验证 |
| `/c/c/agree/opAgree` | 帖子、评论及楼中楼点赞或撤销 | 协议参考已核对，真实账号请求待验证 |

| `/c/c/forum/unfavolike` | 取消关注吧 | 协议参考已核对，真实账号请求待验证 |
| `/c/c/post/add` | 原生文字评论和楼层回复 | 官方 APK 字段已核对，当前使用兼容签名表单，服务端接收及发布结果待验证 |

点赞、关注和评论请求串行提交，操作期间禁止重复触发；未登录时进入官方登录流程。错误和验证码要求显示明确提示，不假装成功。评论按账号、帖子和目标楼层保存草稿；发送结果不明、超时或进程中断后，保留草稿和待确认标记，用户确认原帖未发布后才能再次发送。只有错误码成功且有有效回复 ID 时才清空草稿。网络层关闭自动重试与重定向，避免自动重发或将凭据转发到其他地址。

协议参考为 [aiotieba 的公开接口源码](https://github.com/Starry-OvO/aiotieba/tree/master/src/aiotieba/api) 中 `login`、`agree`、`follow_forum`、`unfollow_forum`。本机官方 APK 22.13.1.1 的 `tbclient.AddPost.DataReq` 确认了 `fid`、`kw`、`tid`、`content`、`tbs`、`quote_id`、`floor_num` 和 `reply_uid` 等评论字段；分析结果仅保存在 `.tools/research/AddPostDataReq.java`，没有复制反编译实现到应用中。

初次开发时没有已授权的连接设备。2026-11-11 后续真机验收已连接 PTP-AN00，现有登录态的原生昵称识别和刷新通过，头像图片尚未通过。本轮用户明确选择只验收阅读与界面，没有发送真实评论、点赞或关注请求；真实写操作仍需用户指定测试目标与内容，不能将接入或构建通过写成真实互动通过。

本轮修复了后续页 `forum.is_exists=0` 占位字段导致的误判：Android 吧第 2、3 页实际错误码为 0 且各有 30 条帖子。现仅在首页校验该标记，后续分页保留首页吧元数据，修复发布包已在真机回归。证据见 `.tools/checks/v020-android-public-pages.json` 和 `device-validation.md`。

帖子详情顶部保留官方页面入口，用于查看原帖或完成安全验证。本地书签与百度云收藏仍相互独立；云收藏、删帖及消息接口尚未接入。

## 当前限制

- 产品目标为去广告、重做原生 UI、参考 X 的完整贴吧替代客户端；以下缺口属于后续开发范围，阅读可用不代表整体完成，详见 `product-requirements.md`。
- 没有稳定公开的完整客户端 API 合同，可能遇到风控、字段变化或临时不可用。
- 楼层中的复杂富内容、视频、投票等尚未完整覆盖。
- 本地收藏仅保存在单台设备，未实现备份导出和云同步。
- 未接入系统分享链接打开应用、推送和离线阅读。
- 进程被系统回收后的完整阅读位置恢复、TalkBack、系统大字体、低端机及弱网性能仍需专项验证。
