# 从 0.7.2 到 1.0.0 的开发与验收计划

制定日期：2026-11-15。基线：0.7.2（versionCode26），最近一次业务真机验收为0.7.1。本文是后续计划，不代表其中功能已经实现，也不新增任何真实账号写操作授权。

实施进度：0.7.3已完成历史状态分离、失败重试、请求失效、同步时间、内存阅读锚点及旧私信开关的代码；139项本地JUnit通过。当前功能和逐项写入证据见[统一台账](feature-status.md)，交付检查见[0.7.3记录](iteration-073.md)。用户指定本轮不实机验收，列表位置、真实分页和已有业务链路的本版设备回归仍待进行，不能把0.7.3全部出口条件记为已通过。下表Q项保留0.7.2审计基线。

2026-11-15优先级调整：用户要求先完善群聊，新增0.7.4群聊迭代，先补最近群同步、群资料/共享内容索引、图片连看、权限/消息键、加入请求和本人撤回；真实云写入尚待授权验证，完整成员、退出、附件、后台通知和数据库迁移仍保留。详见[0.7.4记录](iteration-074.md)。其后继续0.8.0发布与回复，原0.8.3中尚未完成的聊天门槛不取消。

2026-11-15验收与增补：0.7.5只读实机读取群资料/非空禁言名单及图库通过，但发现消息类型81、目标资料220012、群资料键盘返回问题，真实群管理写入未验。用户随后补充发帖选吧要求，0.7.6实现百度候选搜索与完整关注列表的筛选/滚动选择，真机11个吧与候选回填通过。见[0.7.5真机](device-validation-075.md)、[0.7.6记录](iteration-076.md)，不据此关闭0.8.0发布闭环或群聊天出口门槛。

## 目标与判断依据

1.0.0应能替代官方客户端完成普通用户的日常贴吧任务：发现内容、浏览、图文和常用媒体发布、完整回复互动、关系管理、消息与吧群、自己的内容管理及账号设置。简洁通过层级和折叠实现，不能靠取消正常业务实现。

继续采用原生Kotlin/Compose，保留现有液态玻璃、五项导航、已选C聊天方案和B播放器。推荐、关注动态、热榜与吧推荐均来自百度；本地收藏、屏蔽、草稿和缓存明确标注本地性质。没有数据时不造数据，没有接口时不造成功状态。

本次以源码、README、迭代记录和本地验收证据审计。原版功能参照为项目此前核对的22.13.1.1，不声称是当前官方最新版；后续按模块重新核对实际可用协议及普通账号权限。旧文档中的“未实现”须结合日期判断，不能把已完成的搜索、图片保存、签到等重新列为零进度。

状态统一为：**未实现 / 已接入 / 本地验证 / 真机只读通过 / 真实写入通过 / 回归通过 / 外部阻塞**。每项状态附版本、样本和证据；接口空列表不证明非空解析，提交返回成功不证明其他客户端能看到，0.7.1的测试数不自动成为0.7.2的测试结果。

## 1.0.0 必须满足的门槛

### 普通用户完整任务

- 登录→找吧/找人→关注→看到真实关注内容→发图文帖→收到回复/@/赞→进入完整原帖并定位楼层/子回复→继续回复→管理自己的帖子和评论。
- 帖子与评论的赞/取消、云收藏增删、关注/取关均经服务端重新读取确认；计数、身份、表情和媒体不因页面不同而冲突。
- 私信与吧群真实双向收发可用，消息归属、失败、重连、历史分页和可用未读/通知行为准确；不能以空会话和模拟回执代替验收。
- 常用图片、视频和语音内容按实际协议支持浏览与发布；正常用户可用的富内容不能静默丢弃。自己的内容与个人资料可在权限范围内管理。
- 举报/屏蔽/黑名单、账号失效恢复与退出、后台通知、外部打开/分享进入、缓存与本地数据管理有完整路径。
- 登录和官方安全校验可使用百度官方HTTPS页面；普通发帖、回复、收藏和聊天等核心业务应有原生流程，不能仅靠网页兜底算完成。

### 可靠性、适配和发布

- 不存在已知未关闭的P0/P1；P2附具体影响和后续安排，不用P2名义隐藏核心业务缺口。
- 错误、取消、弱网、超时和账号切换不丢草稿、不串账号、不自动重复提交；不确定结果通过读回核对，不能直接当失败重发。
- 数据迁移与备份/恢复经过实际文件验证；账号凭据不进入普通导出、诊断日志或公共下载目录。
- 浅深色、字体和界面倍率组合、小屏、键盘、TalkBack及减弱动效可操作；图库/视频/导航保留用户认可的玻璃设计与手势。
- 在固定网络、固定测试内容、固定设备和刷新率下保存性能数据。0.9.2建立并冻结设备基线；验收目标包括连续30分钟刷帖/聊天无崩溃与ANR、无重复分页和持续内存增长，并以实测数据决定卡顿整改，不能用“看起来流畅”替代测量。
- 至少完成全新安装、0.7.x数据升级及正式签名候选包安装路径；发布配置、版本号、哈希、已知限制和用户说明一致。
- 新增功能有相应协议/状态/数据兼容性回归，既有127项测试继续运行；小幅可逆样式变更以构建和布局检查为主，不堆砌仅复述实现的测试。

### 遇到外部协议限制时

先用真实协议及官方客户端行为核对能力，再调查替代受支持接口。服务端拒绝、权限不足、接口停止开放等保留原错误和明确状态，不伪造结果、不通过不安全的通用网络降级绕过。

私信安全认证、基本收发、普通图文发布等核心门槛如果被接口长期阻塞，应保持开发版或RC状态，并向用户解释证据与选项；不能自行把它们从1.0定义中删掉。会员付费、直播、钱包及需要特殊身份的业务逐项核实边界，不承诺“完全复制全部官方商业功能”，也不把它们混入去广告成果。
