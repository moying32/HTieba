# GitHub 更新限流修复

2026-11-21，Asia/Shanghai。用户报告设置页出现“GitHub 请求受限”。旧更新器只读取匿名REST Releases API；该接口受限时无法取得更新信息。

## 实现

- `PublicReleaseUpdates.kt`、`UpdateFeedLoader`优先读取同一仓库的公开Releases Atom订阅，按SemVer排序，保留公开预发布。
- 读取候选版本的官方`expanded_assets`附件片段，沿用标准附件名、唯一universal、唯一APK的选择规则；只接受本仓库、同一tag的HTTPS下载地址。
- 从附件行读取可用SHA256摘要，从发布页确认预发布标记，通过附件HEAD响应取得精确字节长度。页面显示的近似KB/MB不作为校验长度。
- 公开页面不可用或结构不符合预期时，尝试原REST/ETag备用接口；两条路径都失败时显示可重试错误。取消检查不会触发备用请求。
- 成功走公开页路径时不请求REST API。没有引入token、第三方代理或更新服务器；桌面验证沿用系统现有网络代理设置，APK没有硬编码代理。
- 新增jsoup 1.21.2解析本地响应字符串，不执行网页脚本，不读取外部XML实体；MIT授权随APK放在`assets/third_party_licenses/jsoup.txt`。
- 保留独立无账号凭据的更新客户端、官方域名限制、最多4MiB元数据、最多200MiB安装包，以及下载/安装前的长度、摘要、包名、签名、版本、minSdk校验。

## 验收边界

公开网页不占用原REST API的匿名额度，但仍依赖GitHub访问和页面结构，无法保证任意网络均可访问。GitHub Atom只包含其实际返回的近期条目；公开页和REST备用接口仍可能同时不可用。

本次已验证保留数据覆盖安装修复包、9.5.0提示、跳过/重启不提示、手动检查仍提示、下载及校验。9.5.0只是空壳，可验证到“更新已准备好”；确认安装将替换客户端功能，不能将检测通过表述成已完成系统覆盖安装全链路。
