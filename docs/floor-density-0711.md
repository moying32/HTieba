# 楼中楼紧凑排版实机验收

2026-11-22，Asia/Shanghai，13:08完成收尾核对。手机已覆盖安装 `0.7.11-dev.3 / versionCode 39`；本报告所列排版、导航及一致性检查通过。

## 修改与实机发现

| 修改前 | 修改后 | 原因 |
| --- | --- | --- |
| 头像占独立列，正文重复缩进 | 头像并入作者行，正文使用整行宽度 | 减少中文换行与横向浪费 |
| 作者与回复、点赞分别占一行 | 空间足够时与更多操作共用作者行 | 减少重复触控行，不缩小点击范围 |
| 用固定字号倍率判断能否并排 | 测量实际昵称、回复标签与赞数宽度，并保留触控下限 | 首个候选在手机现有字体和界面设置下误入分行，实际测量后修正 |
| 楼主标记挤占作者行 | 楼主标记移至时间信息行 | 保留身份信息，减少作者区域的额外换行 |

## 同内容对照

使用同一台 PTP-AN00、Android 16 手机，以及同一条真实楼中楼回复；正常模式、原界面偏好、系统字体倍率 1.15。对照旧 `dev.1 / 37` 与新 `dev.3 / 39`。

| 测量项 | 修改前 | 修改后 |
| --- | --- | --- |
| 回复语义节点的占用高度 | 541px | 404px，减少约25.3% |
| 正文起点至回复项右边界的可用宽度 | 879px | 1166px，增加约32.7% |
| 普通正文单行文字边界高度 | 79px | 79px |
| 回复、点赞、更多的点击区域 | 均为224×224px | 均为224×224px，互不重叠 |

高度按该回复的作者、正文、元信息和操作节点联合边界计算；可用宽度按正文左边界至回复项最右操作边界计算。不是整页高度、字号缩放或所有评论的通用节省比例。设备物理密度560dpi，224px约64dp，超过48dp下限。
