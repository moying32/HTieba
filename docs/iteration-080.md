# 0.8.0 发布与回复闭环

2026-11-22。版本 0.8.0，versionCode 40。按[开发路线图](roadmap-1.0.0.md)推进。

| 修改前 | 修改后 | 原因 |
| --- | --- | --- |
| 图文编辑器只显示当前上传第几张，发送时无法退出等待 | 可调整图片顺序，逐张显示处理、进度、等待百度确认及失败状态，可停止等待 | 用户能分辨当前进度和失败位置 |
| 已上传图片凭据只异步保存 | 每张图片确认上传后保存凭据，重试跳过已确认图片 | 断网后可从未完成的图片继续 |
| 评论只显示作者名，发送中没有取消入口 | 明确主帖、楼层及子回复目标，可停止等待和核对原帖 | 让回复对象和恢复动作明确 |
| 云收藏按提交响应提示 | 重新读取收藏列表确认操作，待核对记录可在重启后查看 | 服务端尚未确认时保持原有状态 |

使用系统文件选择器保留图片读取权限，每帖最多 9 张。上传转为质量 88% 的 JPEG，最长边不超过 2048 像素，单张压缩后上限 8 MiB。原图被移动或权限失效时可移除并重选。字节全部写出后仍等待百度返回图片标识。

发帖、回复和云收藏按当前账户确认身份并绑定此次请求。应用先保存提交记录，再发送请求。提交前停止可重试，提交后超时或取消等待时可先核对，确认未发再解锁重试，找到已发内容可清除本机草稿。应用重启不会自动重新提交。云收藏最多回读前 100 项，扫描不足以证实移除时保留待核对状态。

## 真机验收清单

1. 在发帖编辑器输入本机测试草稿，选择两张测试图片、调序并关闭，再重启应用检查标题、正文、顺序和图片权限。
2. 在指定测试吧各发一次文字帖和两图帖。拟用标题「氢贴吧 0.8.0 文字验收」和「氢贴吧 0.8.0 两图验收」，正文分别为「版本验收用文字帖。」和「版本验收用图文帖，图片按横图、竖图排列。」。使用两张本机生成的条纹测试图，核对官方端正文、图片顺序、发帖账号及帖子编号。
3. 在指定测试帖或上述测试帖各发送一条主帖评论、一条父楼回复和一条指向现有子评论的精确回复。拟用正文「0.8.0 主帖评论验收」「0.8.0 父楼回复验收」「0.8.0 精确子回复验收」。在官方端核对父楼、子评论和被回复账号。
4. 对指定测试帖先确认收藏初始状态，在两端核对一次添加、一次移除及最终状态。
5. 在上述操作中验证离线、取消及重启恢复。提交结果不确定时先查对应原帖或收藏列表，给服务端留出审核或同步时间。
