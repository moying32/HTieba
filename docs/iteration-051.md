## 签到行为

- 点击后才开始，没有后台自动签到。读取`/c/f/forum/like`的`page_no/page_size/friend_uid`与`has_more`；重复页、未支持格式或中途读取失败均阻止开始写入，不把部分列表当作全部。
- 账号与安全令牌确认后，逐个调用`/c/c/forum/sign`，请求之间间隔650ms，无并行写入、无失败自动重发。同日同账号在本次进程里已由服务器确认的成功项会跳过；重启后重新以服务端结果为准。
- 成功、今日已签到、失败、待处理分别显示；失败保留原因与贴吧错误码。服务端成功码但缺少签到确认不计成功；错误码不靠猜测映射为已签到，而是回读吧资料。
- “停止”完成当前请求后停止，保留结果，未发送项目可继续。“仅重试失败”重新读取关注列表，只选仍关注的失败吧；不重新请求已确认成功或已取关的目标。
- 登录失效、安全验证、频率限制等停止后续请求；账号会话变化阻止继续。切换账号/退出清理本次签到状态，日期按北京时间隔离。操作进行中沿用全局防重复提交锁。
- 结果在本次进程内保存，退出进程不承诺自动续签；应用重启后不自动重发。未覆盖贴吧的会员/补签/历史日期签到或验证码自动处理。

协议结构参考工作区已有研究快照：`.tools/research/api-reference/get_follow_forums.py`、`sign_forum.py`和`lite-reference/UserLikeForumBean.java`、`SignResultBean.kt`。这些是协议参考，不能代替实际百度账号验收。

新增测试覆盖完整分页、重复分页/后页失败、普通与分组关注、空与非法返回、签到结果确认、失败重试目标、顺序执行、停止保留、登录/验证中止及取消传播。54项JUnit、Lint、R8及验签通过。原有玻璃、折射和导航物理代码保持。

实机补验：推荐冷启动、已有内容下拉刷新、关注空态加载及热榜失败后重试均只观察到单一加载圈；上下栏同步收放、发布选吧后缀通过。真实批次12个关注吧全部签到成功，失败0，明细和跨页面结果保留；吧资料独立回读显示今日已签到。无失败项，因此没有执行失败重试。停止操作到达时批次已完成，不算停止/继续通过；这些边界仍以单元测试为证。未发布帖子或保存资料。截图和限制见[真机记录](device-validation.md)。上轮遗留常亮已先恢复0，本轮临时设置最终恢复见收尾记录。
