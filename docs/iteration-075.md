# 0.7.5 群禁言管理

2026-11-15，versionCode29。延续用户“先完善群聊、暂不实机验收”的要求。本轮只做源码开发、离线协议/状态测试、编译和打包；不操作ADB、不调用真实账号接口、不对真实账号执行禁言或解禁。

## 本版功能

- 群资料新增“管理”分页，长按其他账号的群消息也可进入“群禁言管理（吧务）”。沿用C聊天布局、紧凑液态玻璃和主题颜色；名单与发言者列表惰性渲染，长姓名可换行，时长选项随宽度换行。
- 接入百度禁言名单读取，显示昵称、头像和接口原样返回的剩余时长。名单支持刷新、分页、筛选已加载内容；明确显示读取时间与加载范围。读取失败保留旧名单并提示可能过期；缺失或异常响应不当成空名单。
- 可输入目标账号的贴吧UID，或从已加载消息的发言者选择。操作前重新读取账号资料，核对返回UID和有效portrait，不根据昵称猜测身份，也不把全站主页UID等其他编号混作账号UID。
- 从禁言名单选择账号时，必须核对目标portrait。若本机已有匹配发言者可预填UID，仍须通过新资料验证；否则用户输入UID，不能单凭同名解除他人禁言。此限制源于现有名单接口不提供数值UID；尚未实现完整成员或portrait到UID的独立查询。
- 禁言支持1小时、12小时、1天、7天、15天、30天，另有解除禁言。二次确认列明群名/群号、账号昵称/UID、动作与时长。当前登录账号不能成为本入口的操作目标。
- 采用真实HTTPS接口：名单`/mo/q/chat/getFobiddenList`，禁言`/mo/q/chat/operateSpeech`，解禁`/c/c/chatroom/controlSpeak`。严格区分portrait与UID参数，修改前按当前UID获取TBS，验证期间账号会话变更则中止提交。需要吧务权限，由百度验证每次操作，本应用不根据历史发言者身份制造管理权限。
- 写操作复用既有账号代次保护和群操作互斥锁；不与发送/其他群写入同时提交，不自动重试。只有明确成功响应才显示“百度已确认”；不乐观移除名单条目，成功后重新读取名单。回读失败与写入响应分开显示，连接中断时提示先核对结果。
- 名单和目标资料读取各有独立取消/失效代次；关闭面板、换群、编辑UID或切账号后，旧读取结果不能覆盖新界面。取消面板不会把已经提交的云操作当作撤销。

## 界面评审

| Before | After | Why |
| --- | --- | --- |
| 群资料只能查看自己的禁言状态 | 新增独立管理页，支持真实名单与管理请求 | 补齐有权限账号的群发言管理，保持普通聊天简洁 |
| 群消息只支持阅读与本机操作 | 长按其他账号消息可核对目标并进入管理 | 从具体上下文确定操作对象，减少输入错误 |
| 没有群禁言名单入口 | 头像/昵称/原始剩余时长，分页和已加载筛选 | 不用猜测到期时间，也不把分页中的内容说成全量 |
| 名单没有可直接使用的数值UID | 新资料核对UID与portrait后才允许确认 | 同名和头像回退不能成为管理对象凭据 |
| 新功能可能增加大量气泡 | 目标集中一张紧凑卡片，名单按行呈现、时长自动换行 | 维持液态玻璃与可读信息密度，复用48dp物理触控控件 |

以上是代码层面的设计与结构评审，未将其作为浅深色、50–150%倍率或TalkBack视觉验收通过的证据。原播放器、图片手势、主导航和60dp消息通知入口继续保留。

## 协议依据与验证边界

依据工作区既有aiotieba-develop研究快照的`get_chatroom_blocks`、`block_chatroom_user`、`unblock_chatroom_user`及`ChatroomBlockDuration`枚举；不声称快照为最新官方协议。本次未使用账号探测端点；接口实时兼容性、普通账号拒绝和真实吧务账号的权限均待验证。新增网络请求均为HTTPS，不扩大既有旧私信单域名例外或关闭证书验证。

本版只补齐群禁言管理的代码，不等于完整群管理完成。云端已加入群目录、完整成员/管理员名单、退群、群资料修改、媒体附件发送、原生@与引用、后台通知和结构化聊天数据库仍待开发；真实双向文字发送、加入和撤回继续保留原验收门槛。现有100会话/每会话400消息JSON缓存边界不变。
