# 0.7.4 群聊补齐

2026-11-15，versionCode28。用户将群聊提到下一阶段优先级，本版在0.8.0发布/回复闭环前补齐群聊；其余1.0路线不取消。本轮遵循此前“暂时不实机验收”，没有操作ADB、读取真实账号、发送消息、加入真实群或撤回真实内容。

## 本版实现

- 消息页对本机最近打开的群进行前台同步，每轮最多4群并轮换；手动刷新可遍历本机群会话，显示处理计数并允许停止本轮。成功更新时间和本机未看标记，失败分群显示、暂停该群自动重试，用户可手动重试。不冒充百度云端全部已加入群，也不是后台推送。
- 吧资料增加“查看吧群”，进入当前吧的真实群目录。目录查询变更取消旧请求，关闭取消并使旧结果失效。取消查找返回来源页面，选群后返回原来源；嵌套页面快照保留原聊天选择。
- 群资料采用“资料 / 发言者 / 图片 / 帖子 / 本机收藏”五个分页。资料显示百度返回的群名/头像、成员数、群号（可复制）、所属吧及入口、公告、发言等级门槛、当前账号禁言状态与机器人。缺少权限字段保持未知，不造成员身份。
- 发言者仅从已加载消息去重整理，明确标为“已加载消息的发言者”，支持姓名/UID搜索和进入主页，不能替代全量成员名单。图片/帖子/本机收藏可搜索、定位原消息，图片能打开当前会话已加载图片的连续图库；继续加载更早消息可扩展索引。
- 会话增加日期分隔、准确时分、长按查看完整时间、真实吧内等级，以及阅读中段的“回到最新消息”。新增内容仍只在靠近底部时跟随，不因刷新强行跳走；0.7.3历史边界与稳定消息键继续保留。
- 群发送前重新读取群资料与当前吧内身份；已禁言禁用发送。保留真实`msg_key`，临时回执显示“已提交，待历史确认”，后续历史优先按键一对一核对，不拿同文案的另一条消息冒充确认。无旧键的历史缓存仍保留旧的一对一文字/时间兼容。
- 提交后连接中断保留草稿和结果不确定标记，发送按钮锁定，提供先刷新核对和显式解锁入口，不自动重发。提交前资料读取失败可直接重试。引用仍以文字发送，不宣称百度原生引用或云端@。
- 接入显式群加入请求（BLCP MCAST / 201），确认目标后才提交；只在百度明确回执后显示“已确认请求”，随后刷新，不保存虚假的“已入群”标志。
- 接入本人群消息撤回（`/c/c/chatroom/withdrawMsg`），仅对本人、正数群/吧/消息ID及完整`msg_key`显示入口，二次确认后提交；实际权限/时限由百度决定。成功后本机显示撤回占位，旧缓存回读不覆盖该占位，已选择的撤回消息也不会再作为文字引用带入发送。请求异常不伪造成功，不自动重试。
- 账号、请求代次和会话键共同保护群同步与动作完成回调；切换账号取消旧请求，旧结果不能再修改本地记录。所有新增写入仅为代码接入，真实行为尚待授权验收。

## 界面取舍

| Before | After | Why |
| --- | --- | --- |
| 最近群仅在打开时刷新 | 前台分批同步、分群失败提示和手动刷新 | 让收件箱具备实用的群消息更新能力 |
| 群资料只有名称和公告 | 五个分页，权限、发言者和共享内容分层 | 提升信息完整性，同时维持紧凑C方案 |
| 一张图片一个预览 | 会话连续图库，索引可定位原消息 | 方便查看上下文及相关图片 |
| 临时回执与历史消息缺少区别 | 明示待历史确认、按真实键关联 | 避免把提交回执当作接收方已收到或已读 |
| 发送异常仅提示文字 | 保留草稿、核对结果、显式解锁 | 防止超时后连续点击造成重复消息 |
| 群成员与权限没有信息层级 | 真实权限、历史发言者和未接入全名单分别标明 | 不用推测补造云状态 |
| 缺少加入和撤回入口 | 明确目标与确认，服务端确认后更新 | 完善实际群操作，同时不伪造成功 |

使用已有`GlassPanel`、紧凑胶囊和菜单；新增常驻行不分配独立背景模糊。保留至少48dp物理触控、主题文字颜色和可增高布局。消息页三项通知入口继续60dp视觉高度；播放器、图片手势、主导航及转场参数不作改动。上述为源码层面的设计实现，不能视为浅深色/大倍率的视觉验收通过。

## 协议依据与边界

依据仓库内既有aiotieba协议研究快照：`get_chatroom_detail`、`get_roomlist_by_fid`、`get_chatroom_msgs`、`join_chatroom`、`send_chatroom_msg`及`withdraw_chatroom_msg`。字段对应群资料、历史消息、MCAST201加入请求、185文字提交及HTTPS撤回；不猜测成员、退出、附件和@协议，也不宣称参考快照是最新官方协议。

群连接沿用`common.lcs.baidu.com:443`和证书主机校验；新功能不增加明文域名例外。旧私信的首次认证缺少TLS保护问题仍未解决，保持原授权、原单域名例外及独立开关。加入请求的云成员含义、真实发送与另一端可见、撤回生效均尚未真实验证。
