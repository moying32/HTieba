## 实现与真实能力边界

- 新增 `NativeChatScreens.kt`、`ChatController.kt`。全部使用 Kotlin/Compose，未嵌入设计稿网页。保留原液态玻璃材质、主题与字体、独立50–150%倍率、既有导航/播放器动画。输入栏单独采样背景，避免采样自身；常驻重复按钮不分配独立模糊。
- 左滑直接跟手，按距离或快速有效左滑触发引用，松手按速度弹簧复位；长按菜单提供替代操作。系统返回先退出多选/搜索，资料弹层用平台关闭行为。引用输入摘要可定位已加载原消息；引用发送为明确的文字引用，不伪造百度原生回复关系。
- 搜索只覆盖已加载和本机缓存内容。会话置顶、本地收藏、草稿和“本机未看”按账号隔离；不冒充百度未读/已读回执。缓存每会话保留最近400条、最多100会话；草稿单独保存，不逐字重写聊天记录。完整云历史、跨设备已读同步仍未实现。
- 群目录、资料、公告及分页历史复用既有百度 HTTPS 接口，补取昵称和头像。原生会话前台每15秒读取，离开或进入后台停止，不声明为实时推送。图片/帖子仅在接口实际提供对应字段时显示，复用原图库和帖子入口。未知类型有文字占位，不伪造内容。
- 新增 `GroupChatTransport.kt`：LCM凭据→TLS BLCP登录→IM身份→群文字发送。验证系统证书与主机名，不自动加群、不重试发送；只在百度返回成功回执后加入本地消息。随后与历史中同一条回执合并，保留真实重复文本。发送失败/结果不明保留草稿及引用，进程重启后仍提示先核对。
- 新增旧私信 WebSocket/protobuf 适配初稿：RSA交换随机密钥、协议规定的AES/PBKDF2封包、登录身份校验、私信同步与发送回执。**本版本原生旧私信连接保持关闭**：已检查公开端点443/8000的TLS握手均失败；放行旧连接的网络配置被自动审批拒绝，用户要求先解释、未明确同意。目前未添加明文域名例外，私信发送控件禁用并保留官方HTTPS入口。这不代表私信收发已完成。
- 未添加虚构会话、头像、群成员、在线/输入中/已读状态。群成员完整列表、媒体附件发送、撤回、编辑、后台推送与完整聊天历史继续待接入。
- 协议研究参考本地 `aiotieba-v482` 的 websocket、upload_ws_sec、get_group_msg、send_msg、get_lcm_token、login_blcp_lcm/im、send_chatroom_msg 与 Rpc/Lcm proto。其本地LICENSE为Unlicense。业务逻辑为原生适配，不引入Python运行时。

## 验证记录

首轮新增测试发现 `Long? ?: 0` 在泛型排序中混入Int而导致运行时比较异常，改为明确的 `0L`；同时修复重复批次消耗多个本地回执、早期分页受缓存上限截断、旧账号/旧会话请求回写，以及取消旧请求影响新请求加载状态。

测试重点为嵌套JSON身份/头像/图片、缺失和失败响应、protobuf长度/标签/空字段/64位ID、gzip膨胀限制、独立AES协议样本、真实重复消息与本地回执合并、400条以外的内存历史、账号缓存格式。

本轮没有安装或操作用户手机，没有发送真实私信/群消息。Compose布局仅经过源码与构建检查；浅深色、字号/界面倍率组合、键盘/触控/TalkBack、手势和真实群发送均须后续设备验收，不能把设计稿浏览器验证或单元测试视为原生实机通过。
